# Asset Workflow

## 1. Intake

Create an item when Atlas or Orion completes a milestone with a clear outcome. Record the source project, objective, audience, evidence, and possible asset types.

## 2. Select the audience and outcome

Choose one primary audience and one purpose. Examples: help junior DBAs understand recovery testing; demonstrate Python automation skill to potential employers; explain a data-platform decision to practitioners.

## 3. Create from evidence

Use verified commands, screenshots, measurements, architecture notes, or source code. Do not create claims that cannot be supported by the original work.

## 4. Sanitize and review

Remove credentials, hostnames, internal URLs, personal information, proprietary data, and sensitive logs. Confirm licenses and attribution. Use the quality checklist.

## 5. Publish and record

Publish through the appropriate channel. Store the canonical URL, publication date, version, related source work, and a short retrospective in `published/`.

## 6. Improve and repurpose

Use feedback and metrics to improve the most valuable materials. Reuse an asset only when the new format adds value for a different audience or purpose.
